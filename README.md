# Project Deck (نسخهٔ ۰٫۲)

داشبورد شخصی برای سازمان‌دهی، پیش‌نمایش و اجرای پروژه‌های HTML، بدون بک‌اند و بدون build، مناسب GitHub Pages.

- **نمای بازدیدکننده:** فقط دادهٔ منتشرشده را می‌بیند؛ می‌تواند جستجو کند، علاقه‌مندی بزند و پروژه‌ها را اجرا کند.
- **نمای مدیر** (ورود با شماره و رمز): افزودن، ویرایش و حذف پروژه، مدیریت دسته‌ها، پشتیبان‌گیری و بازیابی.

> **هشدار امنیتی:** چون بک‌اند نیست، ورود مدیر فقط یک **قفل رابط کاربری** است، نه امنیت واقعی. هر کسی که کد را بخواند می‌تواند آن را دور بزند، و آنچه در `data/projects.json` منتشر می‌کنید (حتی پروژه‌های «پنهان») برای همه قابل خواندن است. کنترل واقعی روی محتوا همان دسترسی نوشتن به مخزن GitHub شماست. رمز در هیچ فایلی به‌صورت متن ساده نیست؛ فقط هش PBKDF2 در `data/auth.json` است.

## ساختار
```
project-deck/
├─ index.html  README.md  TESTING.md  PROJECT-SPEC.md
├─ data/projects.json    دادهٔ منتشرشده (دسته‌ها، برچسب‌ها، پروژه‌ها)
├─ data/auth.json        هش ورود مدیر (متن ساده نیست)
├─ assets/css/           theme.css (هویت بصری)  style.css
├─ assets/js/            app.js auth.js admin.js manage.js data-manager.js import-export.js
│                        projects.js categories.js library.js validators.js router.js
│                        storage.js filters.js preview.js icons.js utils.js boot-check.js
├─ assets/               thumbnails/ fonts/ audio/ backgrounds/ icons/ images/  (هرکدام README.txt)
└─ projects/             پروژه‌های شما (نمونه: demo-project)
```

## راه‌اندازی محلی
مرورگر با `file://` ماژول‌ها را مسدود می‌کند؛ از سرور ایستا استفاده کنید:
```
cd project-deck
python3 -m http.server 8000
```
سپس `http://localhost:8000` را باز کنید. (ورود مدیر به https یا localhost نیاز دارد.)

## انتشار در GitHub Pages
1. مخزن تازه بسازید و محتوای پوشهٔ `project-deck` را در ریشهٔ آن commit و push کنید.
2. Settings ← Pages ← Source: «Deploy from a branch»، شاخهٔ `main`، پوشهٔ `/ (root)` ← Save.
3. بعد از چند دقیقه: `https://<user>.github.io/<repo>/`. همهٔ مسیرها نسبی‌اند و به نام مخزن وابسته نیستند.

## افزودن پروژه (فقط مدیر)
**HTML نسبی:** پوشهٔ پروژه را در `projects/` بگذارید (مثلاً `projects/inflation/index.html`) و commit کنید. در داشبورد: «ورود مدیر» ← «افزودن پروژه» ← «انتخاب پوشهٔ پروژه…» (یا تایپ مسیر). مرورگر فقط نام و مسیر را می‌دهد؛ محتوای فایل خوانده یا آپلود نمی‌شود و برنامه می‌گوید فایل در سایت هست یا نه.
**سایت مستقل:** نوع «سایت مستقل» و نشانی کامل `https://…`.
بدون بک‌اند آپلود فایل ممکن نیست؛ کپی‌کردن فایل‌ها در `projects/` با خود شماست.

## انتشار تغییرات مدیر (مهم)
هرچه در داشبورد اضافه می‌کنید یک **پیش‌نویس** در `localStorage` همان مرورگر و **همان آدرس** است. `localhost:8000` و `https://<user>.github.io/<repo>/` دو آدرس جدا هستند و پیش‌نویس هم‌دیگر را نمی‌بینند. بازدیدکنندگان (و خود شما بدون ورود) فقط `data/projects.json` را می‌بینند. برنامه پوشهٔ `projects/` را خودکار اسکن نمی‌کند، چون سایت ایستا نمی‌تواند محتوای پوشه را فهرست کند؛ هر پروژه باید در `data/projects.json` ثبت باشد.

برای انتشار:
1. در نسخهٔ محلی: «ورود مدیر» ← «داده‌ها» ← **«دریافت projects.json برای انتشار»**.
2. فایل را در مخزن به‌جای `data/projects.json` بگذارید.
3. پوشهٔ پروژه‌ها (`projects/...`) و تصویرها را هم commit کنید، سپس push.
4. چند دقیقه صبر کنید و صفحه را با Ctrl+Shift+R رفرش کنید.

اگر روی GitHub Pages چیزی دیده نشد، بررسی کنید: `https://<user>.github.io/<repo>/data/projects.json` را مستقیم باز کنید؛ باید پروژه‌های شما در آن باشد. بعد مسیر یک پروژه (مثلاً `…/projects/inflation/index.html`) را باز کنید. GitHub Pages به **حروف بزرگ و کوچک حساس** است (`Projects/` با `projects/` فرق دارد) و فایل‌های commit‌نشده را ندارد.

## تصویر پوشش، فونت، آیکون، صدا، پس‌زمینه
هر پوشهٔ `assets/…` یک README.txt با قالب و نام‌گذاری دارد. خلاصه:
- **تصویر:** `assets/thumbnails/<project-id>.webp` (۱۶:۹) و در فرم «انتخاب تصویر…».
- **فونت:** فایل `.woff2` در `assets/fonts/` و فعال‌کردن `@font-face` در بالای `style.css`.
- **آیکون Tabler:** `assets/icons/tabler-sprite.svg`؛ بدون آن ایموجی استفاده می‌شود.
- **صدا:** `assets/audio/ambient.mp3`؛ هرگز خودکار پخش نمی‌شود.
- **پس‌زمینه:** `assets/backgrounds/background.webp`.
همه اختیاری‌اند و نبودنشان چیزی را خراب نمی‌کند.

## پشتیبان‌گیری و بازیابی
«داده‌ها» (فقط مدیر): دریافت پشتیبان (`project-deck-backup-YYYY-MM-DD.json`)، وارد کردن (با خلاصه، «جایگزینی کامل» با تأیید صریح یا «ادغام» با سیاست تداخل: نگه‌داشتن فعلی (پیش‌فرض) / جایگزینی / کپی با شناسهٔ تازه)، بازنشانی به داده‌های نمونه و پاک‌کردن دادهٔ محلی. پشتیبان فقط پیکربندی است نه فایل‌های پروژه، و هیچ‌کدام از این عمل‌ها فایل پروژه‌ای را پاک نمی‌کنند.

## نشانی‌های قابل اشتراک
`?category=finance`، `?view=favorites`، `?category=finance&search=تورم`. شناسهٔ دسته با تغییر نام عوض نمی‌شود.

## محدودیت‌های ذخیره‌سازی مرورگر
پیش‌نویس مدیر، علاقه‌مندی‌ها و سابقه در `localStorage` همین مرورگر و همین آدرس‌اند و بین دستگاه‌ها همگام نمی‌شوند. پاک‌کردن داده‌های مرورگر آن‌ها را حذف می‌کند، پس پشتیبان بگیرید. اگر ذخیره‌سازی بسته باشد، برنامه با حافظهٔ موقت ادامه می‌دهد و پیام می‌دهد.

## محدودیت‌های iframe
- پیش‌نمایش فقط با درخواست کاربر بارگذاری می‌شود (هیچ‌وقت همه‌چیز هم‌زمان).
- بسیاری از سایت‌ها نمایش در قاب را مسدود می‌کنند و مرورگر این را قابل‌اعتماد گزارش نمی‌دهد؛ «باز کردن مستقل» همیشه هست و بعد از ۱۲ ثانیه پیام جایگزین می‌آید.
- پروژهٔ محلی `allow-same-origin` دارد (برای localStorage خودش)؛ فقط پروژه‌های خودتان را اجرا کنید. سایت خارجی بدون آن و فقط با مجوز تمام‌صفحه بارگذاری می‌شود.

## امنیت در کد
CSP در `index.html` (فقط منبع همین سایت)، همهٔ متن‌های ورودی با escape درج می‌شوند، `eval` ندارد، فایل ورودی فقط به‌عنوان داده تحلیل می‌شود، لینک‌های بیرونی `noopener noreferrer` دارند، مسیرها و نشانی‌ها اعتبارسنجی می‌شوند.

## تغییر شماره و رمز مدیر
مدیر: «تنظیمات و راهنما» ← «تغییر اطلاعات ورود»؛ فایل `auth.json` تازه دانلود می‌شود. آن را به‌جای `data/auth.json` بگذارید. رمز طولانی و تصادفی انتخاب کنید، چون هش در مخزن قابل دانلود است.

## محدودیت‌های شناخته‌شده
- ورود مدیر امنیت واقعی نیست (بالا را ببینید).
- نبودن آپلود و بک‌اند؛ همگام‌سازی بین دستگاه‌ها دستی است (پشتیبان).
- جابه‌جایی دسته‌ها با دکمه است، نه کشیدن‌ورها کردن.
- نبودن فایل HTML هنگام «اجرا در تب جدید» از پیش تشخیص داده نمی‌شود (در فرم و در پیش‌نمایش زنده می‌شود).
- آزمون‌ها فقط روی Chromium انجام شده است؛ Firefox، Safari و دستگاه واقعی را خودتان با `TESTING.md` بررسی کنید.
