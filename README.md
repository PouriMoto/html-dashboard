# Project Deck

داشبورد شخصی برای سازمان‌دهی، پیش‌نمایش و اجرای پروژه‌های HTML. فقط HTML، CSS و JavaScript ساده؛ بدون بک‌اند و بدون build. مناسب GitHub Pages.

پروژه‌ها و دسته‌ها را از داخل خود داشبورد مدیریت می‌کنید؛ لازم نیست JavaScript یا JSON را دستی ویرایش کنید.

## ساختار
```
project-deck/
├─ index.html
├─ README.md  PROJECT-SPEC.md
├─ data/projects.json          داده‌های اولیه (دسته‌ها، برچسب‌ها، پروژه‌ها)
├─ assets/
│  ├─ css/   theme.css (هویت بصری)  style.css (چیدمان و اجزا)
│  ├─ js/    app.js router.js storage.js projects.js categories.js library.js
│  │         validators.js manage.js preview.js filters.js import-export.js icons.js utils.js
│  └─ thumbnails/ fonts/ audio/ backgrounds/ icons/ images/   (هرکدام README.txt)
└─ projects/demo-project/      پروژهٔ نمونه
```
`utils.js` و (در این مرحله) `router.js`، `library.js`، `validators.js` و `manage.js` به ساختار اولیه اضافه شده‌اند تا هر ماژول یک مسئولیت داشته باشد.

## اجرا
مرورگر با `file://` ماژول‌ها و `fetch` را مسدود می‌کند، پس `index.html` را مستقیم باز نکنید:
```
python3 -m http.server 8000      # سپس http://localhost:8000
```

## انتشار در GitHub Pages
پوشه را در یک مخزن بگذارید (`index.html` در ریشه) و در Settings، بخش Pages، شاخهٔ `main` و پوشهٔ `/ (root)` را انتخاب کنید. همهٔ مسیرها نسبی‌اند و نام کاربر یا مخزن در کد نیست.

## مدیریت از داخل رابط
- **افزودن/ویرایش/حذف پروژه:** دکمهٔ «افزودن پروژه» در هدر؛ دکمه‌های ویرایش و حذف روی کارت‌ها (در «حالت مدیریت»، که پیش‌فرض روشن است و از منوی «داده‌ها» خاموش می‌شود).
- **دسته‌ها:** «مدیریت» کنار عنوان دسته‌ها، یا منوی «داده‌ها». ساخت، تغییر نام و توضیح، ایموجی/آیکون، ترتیب، پنهان‌کردن از منو و حذف (با انتقال پروژه‌ها یا بی‌دسته‌گذاشتن‌شان؛ هیچ پروژه‌ای هرگز با حذف دسته پاک نمی‌شود).
- **ورود و خروج JSON:** منوی «داده‌ها».

### مسیر و نشانی
- فایل HTML محلی: مسیر نسبی داخل `projects/`، مثل `projects/inflation/index.html`. مسیرهای شامل `..`، `/` ابتدایی، فاصله، `http:` یا کدگذاری پنهان رد می‌شوند و هیچ مسیر نامعتبری بی‌صدا «درست» نمی‌شود.
- سایت مستقل: فقط `http://` یا `https://`، بدون نام‌کاربری و رمز.
- تصویر پوشش: فایلی از قبل داخل `assets/` (مثلاً `assets/thumbnails/x.webp`). تصویر ناموجود به گرادیان و ایموجی برمی‌گردد.

### آپلود فایل وجود ندارد
این سایت ایستاست و نمی‌تواند فایل را در مخزن بنویسد. فایل‌های HTML جدید را خودتان در `projects/` بگذارید (و commit کنید) یا جای دیگری منتشر کنید؛ بعد مسیر یا نشانی را در فرم وارد کنید. یک آپلودر واقعی به یکپارچه‌سازی یا بک‌اند جداگانه نیاز دارد و خارج از این نسخه است.

### حالت‌های پیش‌نمایش
| حالت | رفتار |
|---|---|
| فقط تصویر (پیش‌فرض) | جزئیات با تصویر پوشش؛ اجرا در تب جدید |
| پیش‌نمایش زنده | پنجرهٔ iframe با وضعیت بارگذاری، دکمهٔ بستن، «باز کردن مستقل»، تمام‌صفحه و پیام جایگزین |
| تب جدید | اجرا مستقیم در تب جدید با `noopener noreferrer` |

هیچ‌وقت همهٔ پروژه‌ها هم‌زمان در iframe بارگذاری نمی‌شوند. بسیاری از سایت‌ها نمایش در قاب را مسدود می‌کنند و مرورگر این را به‌طور قابل‌اعتماد گزارش نمی‌دهد؛ برای همین یک راهنما و دکمهٔ «باز کردن مستقل» همیشه دیده می‌شود، و اگر ۱۲ ثانیه چیزی لود نشود پیام جایگزین می‌آید. برای فایل‌های محلی، نبودن فایل پیش‌تر تشخیص داده می‌شود.

### نشانی‌های قابل اشتراک
```
index.html?category=finance
index.html?view=favorites
index.html?category=finance&search=تورم
```
`view` یکی از `home`، `library`، `favorites`، `recent`، `settings` است. نشانی نامعتبر به نمای امن برمی‌گردد. شناسهٔ دسته (slug) هنگام ساخت تعیین می‌شود و با تغییر نام عوض نمی‌شود، پس لینک‌های قبلی کار می‌کنند.

## ذخیره‌سازی
تغییرات در `localStorage` (پیشوند `projectdeck.v1.`) ذخیره می‌شوند و مخصوص همین مرورگر و همین آدرس‌اند؛ همگام‌سازی خودکار بین دستگاه‌ها وجود ندارد. اگر ذخیره‌سازی در دسترس نباشد، پیام دیده می‌شود و تغییرات تا بستن صفحه می‌مانند. داده‌های خراب کنار گذاشته و نسخهٔ پشتیبان آن‌ها در `projectdeck.v1.library.corrupt` نگه‌داری می‌شود. برای انتشار دائمی، «دریافت خروجی JSON» را بزنید و فایل را به‌جای `data/projects.json` در مخزن بگذارید.

## سفارشی‌سازی ظاهر
همهٔ هویت بصری در `assets/css/theme.css` است: `--accent` (رنگ اصلی)، `--accent-2` (رنگ ثانویه کم‌مصرف)، پس‌زمینه‌ها، شعاع گوشه‌ها، `--font-ui` و `--bg-image`. با عوض‌کردن همین مقدارها ظاهر عوض می‌شود. فونت، تصویر، پس‌زمینه، صدا و آیکون: README.txt هر پوشهٔ `assets/` را ببینید. بدون هیچ‌کدام همه‌چیز کار می‌کند.

## نکتهٔ امنیتی
پروژه‌های محلی در پیش‌نمایش زنده هم‌مبدأ با داشبورد هستند (`allow-same-origin`) تا `localStorage` خودشان کار کند؛ فقط پروژه‌های خودتان را اجرا کنید و کلیدهای `projectdeck.v1.*` را تغییر ندهید. سایت‌های خارجی بدون `allow-same-origin` و فقط با مجوز تمام‌صفحه بارگذاری می‌شوند.

## محدودیت‌های شناخته‌شده
- با `file://` کار نمی‌کند.
- داده‌ها همگام نمی‌شوند و آپلود فایل وجود ندارد.
- نبودن فایل HTML محلی هنگام «اجرا در تب جدید» از پیش تشخیص داده نمی‌شود (در فرم و در پیش‌نمایش زنده تشخیص داده می‌شود).
- جابه‌جایی دسته‌ها با دکمه‌های بالا/پایین است، نه کشیدن‌ورها کردن.
